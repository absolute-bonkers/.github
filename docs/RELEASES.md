# Recognition and releases

## Contributor recognition

Every contribution remains discoverable in the repository's commit history and
GitHub **Insights → Contributors** graph. Release notes can call out notable
corrections, new examples, and contributors when a module reaches a meaningful
milestone. Recognition is opt-in: include a preferred name or GitHub handle in
the pull request if you want a release note to mention you.

## When to make a release

Create a GitHub Release when a module has a useful, reviewable milestone, such
as a completed topic group, a substantial accuracy pass, or a meaningful
example/test improvement. Routine typo fixes do not need a release.

Use a repository-local version tag such as `v1.0.0` for the first curated
release, then increment the version for later milestones. Keep the release
notes concise: summarize learner-facing changes, mention compatibility or
behavior changes, and credit contributors who opted in. Do not imply that
educational examples are production-ready.
