# Contributing to Absolute Bonkers

Thanks for helping make system design easier to learn. Contributions of all
experience levels are welcome, especially clear explanations, corrected
references, small runnable examples, and tests.

## Ways to contribute

- Ask or answer questions in the repository's GitHub Discussions.
- Suggest a new topic or report a content issue with the issue forms.
- Improve a guide, example, test, link, or accessibility.
- Pick an issue labeled `good first issue` for a scoped starting point.

## Before opening a pull request

1. Choose the module repository that owns the topic and open an issue or
   discussion first for substantial changes.
2. Keep changes focused on one topic and explain the learning goal.
3. Cite primary specifications or official documentation for factual claims;
   use reputable educational references as supplemental reading.
4. Make examples self-contained, safe to run, and clear about limitations.
5. Run the repository's documented tests or checks. For Gradle repositories,
   run `./gradlew --no-daemon clean test`.
6. Update the topic guide when example behavior changes, and add tests for
   behavioral fixes.
7. Do not include secrets, credentials, personal data, or generated build
   output.

## Pull request expectations

Describe the problem, the change, and how you verified it. Link the related
issue or discussion where applicable. Maintainers may request revisions to
improve accuracy, clarity, or consistency with the learning path.

## Recognition and releases

Contributors are visible in each repository's commit history and
**Insights → Contributors** graph. Significant module milestones may be
recognized in GitHub Releases; see [release guidance](docs/RELEASES.md).

By contributing, you agree that your contributions are provided under the
repository's MIT License.
